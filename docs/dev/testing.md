# 검증

고친 뒤에는 `npm run check`를 돌립니다. 자동 검사는 모두 LLM 없이(규칙 모드로) 돌기 때문에 API 키가 필요 없습니다.

## 검사 명령

| 명령 | 하는 일 | 키 |
|---|---|---|
| `npm run check` | 아래 셋을 차례로 실행 | 없음 |
| `npm run lint` | ESLint. 가져오기 누락(`no-undef`), 겹친 열쇠, 안 쓰는 변수. 형식은 보지 않음 | 없음 |
| `npm test` | 시험 26종 | 없음 |
| `npm run regress` | 회귀 지문을 기준선과 견줌 | 없음 |
| `node tools/balance.mjs 45` | 자동 플레이 봇으로 45일. 오류 없이 끝나는지와 경제 곡선 | 없음 |
| `node tools/share-check.mjs` | 접속 코드·한도·파일 보호 19항목 ([서버와 공유](server.md)) | 필요 (열 번쯤 호출) |
| `node tools/probe.mjs` | 켜져 있는 서버의 LLM 중계가 응답하는지 | 필요 |

- `_helpers.mjs`의 `fresh(씨앗)`이 새 게임을 만들어 줍니다.
- `todo` 2종은 알려진 문제([A-1, A-18](../roadmap/known-issues.md))를 적어 둔 것입니다. 실패해도 전체 결과를 막지 않습니다. 문제를 고치면 `todo` 표시를 떼어 계속 지키게 합니다.
- 사건 유형·의제·행위자·장을 더했다면 `content`와 `campaign`이 형식과 "없는 것을 가리키는" 실수를 먼저 잡습니다.
- 시험을 통과시키려고 범위를 줄이거나 기대값만 맞추지 않습니다.

## 회귀 지문

`tools/regression.mjs`는 정해진 씨앗과 정해진 행동(취재, 발행, 도장, 채용, 지국)으로 30일을 돌린 뒤 게임 상태 전체의 SHA-256을 `tests/fixtures/regression-baseline.json`과 견줍니다.

- **구조만 바꾼 PR에서 지문이 달라지면 동작이 바뀐 것입니다.** 원인을 찾습니다.
- 규칙·밸런스·데이터를 일부러 바꿨다면 달라지는 것이 정상입니다. `node tools/regression.mjs --update`로 기준선을 새로 적고 PR에 "지문이 바뀜"과 까닭을 적습니다.

## 손으로 확인하는 것

화면(`public/js/ui/`)과 실제 LLM의 응답은 자동 시험이 없습니다. 브라우저에서 직접 확인하고, PR의 "확인 방법"에 **자동 검사로 확인한 것과 실제 모델로 확인한 것을 구분해** 적습니다.

| 방법 | 쓰임 |
|---|---|
| 주소에 `?dev=1` | 타이틀을 건너뛰고 고정 씨앗·고정 이름으로 시작 |
| 주소에 `?dev=1&skip=1` | 프롤로그까지 건너뛰고 도장을 가진 채 시작 |
| 콘솔 `__dev.G` | 게임 상태 |
| 콘솔 `__dev.skip(분)` | 시간을 한꺼번에 보냄 |
| 콘솔 `__dev.setSpeed(0~3)`, `__dev.emit(…)`, `__dev.showEvent(id)`, `__dev.saveGame()` | 속도, 이벤트 발생, 사건 열기, 저장 |
| 콘솔 `await import("/js/sim/world.js")` | 어떤 모듈이든 불러 함수를 직접 써 봄 |
| `GET /api/health` (내 PC) | LLM 작업별 호출 수와 오류 수 |

실제 LLM으로 확인한 범위는 프롤로그 전체, 제1장의 서울·제네바 무대, 환원 두 가지, 이동, 같은 PC에서의 공유 접속입니다. 아직 확인하지 못한 것은 [알려진 문제](../roadmap/known-issues.md)의 B 항목에 있습니다: 제1장 리옹·나이로비·런던의 인터뷰(B-1), 긴 샌드박스 플레이(B-2), 소리(B-3), 다른 기기에서의 공유(B-4), 다른 브라우저(B-5), 비용과 지연(B-6), 판정의 한결같음(B-7), 긴 플레이의 세이브(B-8).

## 알아 둘 점

- **탭이 가려지면 게임 시계가 멈춥니다.** `requestAnimationFrame`이 멈추기 때문입니다. 자동화 도구로 화면을 볼 때는 `__dev.skip(분)`으로 시간을 보냅니다.
- **구조화 출력의 한계.** 스키마의 속성 수가 많으면(수십 개) API가 거절합니다. 속성 순서가 생성 순서이므로 대사·본문을 맨 앞에 둡니다. 사고를 켜면 사고가 출력 상한을 먼저 쓰므로 상한을 넉넉히 잡습니다([LLM 연출](../design/llm.md)).
- **사건 서사 한 건에 10초쯤 걸립니다.** 그래서 미리 써서 쌓아 두는 방식입니다. 가만히 두어도 사건 연출 호출이 나갑니다.
- `npm test`는 폴더가 아니라 `"tests/*.test.mjs"` 패턴으로 부릅니다(Node 24는 폴더 인자를 받지 않습니다). 새 시험 파일은 이 이름 규칙을 따릅니다.
- 점검 도구(`share-check`, `guest-preview`)는 운영체제 임시 폴더에 작은 사용량 파일을 남깁니다.
