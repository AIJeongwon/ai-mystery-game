# LLM 연출

근거: `public/js/llm/api.js`, `llm/tasks/`, `llm/world-rules.js`, `public/js/sim/director.js`, `sim/chronicle.js`, `sim/canon.js`, `sim/press/publish.js`, `public/js/ui/interview.js`, `server/llm.js`, `server/tasks.js`

## 원칙

1. **모델은 하나.** Claude Haiku 5.5, effort low. 서버에서 고정하며 브라우저의 요청으로는 바꿀 수 없습니다.
2. **LLM은 제안하고 규칙 엔진이 결정한다.** 출력은 언제나 JSON 스키마로 받고, 규칙 엔진이 검사·보정한 뒤 받아들입니다. LLM이 세계의 수치를 직접 바꾸는 길은 없습니다.
3. **모든 호출에 규칙 기반 대안이 있다.** 키가 없거나, 한도를 넘었거나, 응답이 깨져도 게임은 계속됩니다.
4. **플레이어가 모르는 것은 LLM도 말하지 않게 한다.** 숨은 진상과 아직 취재하지 못한 사실이 총평이나 대사로 새지 않도록 프롬프트와 검증 양쪽에서 막습니다.
5. **실존하는 이름은 쓰지 않는다.**

## 작업 여섯 가지

| 작업 | 하는 일 | 부르는 때 | 사고 | 출력 상한 (요청 / 서버) | 제한 시간 | LLM이 없을 때 |
|---|---|---|---|---|---|---|
| `director` 사건 연출 | 사건 씨앗에 서사를 입힌다 | 재고를 채울 때, 예약 사건 | 사용 | 4,500 / 5,000 | 75초 | 유형별 규칙 서사 틀(`fb`) |
| `chronicle` 국면 전개 | 전개·수습 국면의 "그 뒤" | 1시간마다 최대 3건을 한 번에 | 사용 | 3,000 / 3,500 | 60초 | 정해진 경과 문장 |
| `npc` 인물 연기 | 취재원으로서 답한다 | 인터뷰 질문마다 | 끔 | 700 / 900 | 40초 | 문턱을 넘은 사실을 그대로 말함 |
| `judge` 기사 판정 | 기사를 사실 목록과 대조해 채점 | 발행, 교열 검토 | 사용 | 3,500 / 4,000 | 70초 | 낱말 겹침으로 판정 |
| `decree` 기정문 해석 | 도장 찍힌 문장을 효과 제안으로 옮김 | 도장 감정 | 사용 | 2,500 / 3,000 | 60초 | 낱말로 대략 해석 |
| `draft` 초안 보조 | 확보한 사실로 초안 작성 | 편집국의 초안 보조 | 끔 | 1,500 / 2,000 | 40초 | 사실을 이어 붙임 |

- 출력은 모두 구조화 출력입니다. 스키마의 속성 순서가 생성 순서이므로 대사·본문을 맨 앞에 둡니다. 스키마가 크면 거절되므로 작게 유지하고 열거형을 씁니다.
- 사고를 쓰는 작업은 사고가 출력 한도를 먼저 쓰므로 상한을 넉넉히 둡니다. 줄이면 JSON이 잘립니다.
- 인물 연기의 시스템 프롬프트는 프롬프트 캐시를 씁니다.
- 사건 서사는 한 건에 10초쯤 걸립니다. 그래서 평범한 사건은 미리 5건까지 써 두고 꺼내 씁니다(`sim/director.js`).

## 프롬프트 공통 규칙

모든 프롬프트에 `llm/world-rules.js`의 세계 규칙이 들어갑니다: 2031년의 가상 세계, 지명은 실제이고 인물·기업·기관·언론사는 모두 허구, 실존 이름 금지, 글은 한글로만(한자·영문·"(가명)" 같은 주석 금지), 외국 인명은 그 문화권에 어울리게 지어 한글로.

## 작업별 장치

| 작업 | 지키는 것 |
|---|---|
| 사건 연출 | 사실은 깊이 0이 2개, 1이 2개, 2가 1개, 3이 1개. 핵심 진상은 우호적이지 않은 한 명만 안다. 거짓 소문은 "~라는 소문" 같은 꼬리 없이 단정문으로 쓴다. 제목과 개요에 날짜를 쓰지 않는다. 규칙 엔진은 사실 4개·취재원 2명 미만이면 버리고, 깊이와 '아는 사실'을 다시 맞춘다 |
| 국면 전개 | LLM에게 언론 압력 값을 보여 줘 규칙 엔진의 결말 판정과 이야기가 어긋나지 않게 한다. LLM이 준 기울기(−1/0/+1)는 0.5씩만 반영한다. 결말을 뒤집지는 못한다 |
| 인물 연기 | 사실마다 '말하는 조건'을 붙인다(바로 / 신뢰도 50 이상이거나 근거를 제시했을 때 / 캠페인의 조건). 규칙 엔진은 `revealed` 가운데 그 인물이 실제로 아는 번호만 수첩에 적는다. 해당하는 기정문은 `[세상의 상식]`으로 넘겨, 도장이 찍힌 뒤에는 인물이 그 문장을 원래 알던 사실로 말한다 |
| 기사 판정 | 사실마다 "기자가 확인함 / 전해 들음 / 아직 모름"을 표시해 넘긴다. 총평에서 '아직 모름'과 진상을 언급하지 않게 한다. 거짓 소문은 단정했을 때만 거짓 주장으로 친다. 〔 〕로 감싼 기정문은 채점에서 뺀다. 캠페인의 환원 기사에는 앞 무대에서 확인한 사실을 덧붙여 넘긴다 |
| 기정문 해석 | "문장의 도덕성이나 사실 여부를 따지지 않고 게임 규칙에 따라 담담히 해석한다." 대상은 넘겨준 목록(최대 44개)의 ID와 속성만 쓴다. 문장이 말하지 않은 효과를 덧붙이지 않는다. 받아들일 범위는 규칙 엔진이 정한다([記定 시스템](canon.md)) |
| 초안 보조 | 주어진 사실에 없는 내용은 보태지 않는다. '전해 들음'은 출처를 한정해 쓴다 |

## 실패 처리

| 오류 | 대응 |
|---|---|
| 속도 제한, 네트워크, API 오류, 잘림, JSON 깨짐, 빈 응답 | 작업에 따라 0~1회 다시 시도한 뒤 규칙 기반 대안 |
| 시간 초과 | 대안으로 넘어감 |
| 키 없음, 인증 실패, 접속 코드 필요·오류·잠금, 하루 예산·한도 초과 | LLM을 끄고 규칙 모드로 전환. 5분마다 다시 확인해 풀리면 돌아온다 |

사건 연출이 네 번 연달아 실패하면 재고 채우기를 멈추고 규칙 서사로 세계를 채웁니다. 접속 코드와 한도는 [서버와 공유](../dev/server.md)에 있습니다.

## 작업을 더하거나 고칠 때

1. `llm/tasks/<이름>.js`에 스키마와 요청 조립 함수를 만듭니다. 시스템 프롬프트에 `WORLD_RULES_TEXT`를 넣고 `maxTokens: TASK_LIMITS.<이름>`을 씁니다.
2. `llm/tasks/limits.js`와 `server/tasks.js`의 `TASK_CAPS`에 같은 이름을 넣습니다. 서버 쪽을 빠뜨리면 바깥 접속자의 호출이 거절되고, 서버 상한이 더 작으면 응답이 잘립니다.
3. `llm/prompts.js`에 내보내기 한 줄을 더하고, 부르는 쪽에 규칙 기반 대안을 둡니다.
4. `tests/llm-tasks.test.mjs`의 요청 목록에 한 줄을 더합니다. 이 시험은 이름·상한·스키마 형식만 봅니다.
5. 프롬프트를 고친 뒤에는 `node tools/probe.mjs`와 브라우저에서 실제 응답을 확인합니다(실제 API 호출). 고정 응답이나 형식 검사로 확인한 것과 실제 모델로 확인한 것은 구분해 적습니다.

전체 순서와 다른 확장 방법은 [기술 구조](../dev/architecture.md)에 있습니다.
